# ROM Finder — Project Guide

## What This Project Is

A self-hosted web app for managing a personal ROM collection with a focus on **RetroAchievements (RA) hash verification**. Core workflow:

1. **Discover** — search RA's game database; add games to the Wanted pool
2. **Find** — search ROM sources (Archive.org, Vimm, etc.) and download
3. **Verify** — hash each ROM and match against RA's accepted hash list
4. **Track** — maintain a library of verified ROMs with cover art

Every ROM kept must be a hash-verified, RA-accepted dump — not just any ROM that runs.

## Stack

| Layer | Technology |
|---|---|
| Backend | Python 3.11, FastAPI (async) |
| Frontend | Jinja2 templates, HTMX 2, Tailwind CSS (CDN) |
| Database | SQLite via SQLModel (sync sessions, async routes) |
| Deploy | Docker on Unraid, GitHub Actions CI/CD → GHCR; Watchtower auto-pulls (see `deploy/`) |
| HTTP client | httpx (async) |
| Headless browser | Playwright (Chromium) — bundled in the Docker image for the Vimm extension's JS-challenge bypass |

**No JS framework.** All interactivity is HTMX. JS in templates is minimal — only for things HTMX can't do (dropdowns, card overlay polling, drag-to-reorder).

## Verifying a Change (agent-driven, no human site checks)

Confirm a change works by pulling machine-readable feedback from the app — never by asking the user to open the site.

- **Fast local run** (no Docker daemon needed): `scripts/run-local.ps1` boots the app from the test venv (`./venv`) on a throwaway DB and prints `/api/status`. Or run `pytest` against the `tests/conftest.py` fixtures (throwaway-DB engine + `TestClient`).
- **Full-image run**: `docker compose -f docker-compose.local.yml up --build -d`, then `curl /api/status` and `curl "/api/logs?level=error"`, then `down -v`.
- **`GET /api/status`** reports version, RAHasher availability, DB counts (incl. `no_ra`), scheduler last-runs, verify progress, sources/extensions, and recent errors. **`GET /api/logs`** is the JSON log feed. These are the source of truth for "did it work?" — the `deploy-verifier` and `prod-health-monitor` agents read them.
- After deploy, confirm `/api/status.version` == the pushed git SHA (also shown on the Settings page).

## Adding a New Feature — Checklist

1. **New DB column?** Add to `models.py` + a new `(version_id, apply_fn)` entry in `app/db/migrations.py`
2. **New setting?** Add to `DEFAULT_SETTINGS` in `app/services/settings.py` — seeded automatically at startup. Read it via `app.services.settings` (`get`/`get_bool`/`get_json`)
3. **New router?** Register in `main.py::app.include_router(...)`. Add nav link in `base.html` if user-facing
4. **New background task?** Use `activity_store.start_batch(..., entry_ids=[...])` for per-card overlays
5. **New cover source?** Subclass `CoverSource` → `app/services/cover_sources/` → register in `registry.py` → add settings to `DEFAULT_SETTINGS`
6. **New ROM source?** Same pattern under `app/services/sources/`
7. **New extension?** Create a `.py` in `extensions/` with `EXTENSION_INFO` + `EXTENSION_SETTINGS` + `SOURCE_CLASS` / `COVER_SOURCE_CLASS`. Add entry to `extensions/index.json`. Extensions install/remove/toggle/update at `/extensions`. Extension settings appear on the Settings page automatically. Settings stored as `ext_{ext_id}_{key}` in AppSetting; passed to `configure(config)` if the source defines it.

## Done (recent stabilization/modularization pass)

- **Hash export** ✅ — `/export/hashes?format=csv|json` (links on Settings)
- **Bulk import** ✅ — the scheduler **Library scan** task (`/scheduler` → Run now, or daily) walks `download_dir`, imports untracked ROMs, hashes (RAHasher-first + disc guard), fetches covers, and RA-verifies — that IS the one-pass importer
- **Bulk RA verify after hash** ✅ — resumable, rate-limit-aware **RA re-verify** scheduler task (`ra_verify.run_pass`)
- **RetroAchievements Dashboard** ✅ — `/dashboard` (Overview / Timeline / Games / Insights / Reports). A **local mirror** of the configured user's RA data (`ra_achievement`/`ra_game_progress`/`ra_profile`), so all metrics/graphs/search/time-filters run with **zero RA calls**. Synced by a **manual** Refresh (`ra_dashboard.refresh()`) that **fully re-pulls + replaces** the mirror — that's how retroactively-changed achievements reconcile. Charts via ApexCharts (CDN); games cross-referenced to the owned library by RA ID; reports export as RetroAchievements forum markup (`ra_report.py`). State surfaces in `/api/status.dashboard`.
- **Live in-place page updates** ✅ — pages mutate in place as background work changes the DB (no manual refresh, no "refresh" prompt) **without losing** scroll / open detail panel / multi-select / half-typed input. A `base.html` poller diffs the cheap **`GET /api/changes`** per-scope fingerprint feed and, on change, **morphs** the current URL's fresh HTML into `#live-content` via **idiomorph** (`hx-ext="morph"`). Opt-in per page via `{% block live_scope %}` (collection/downloads/wanted/logs/scheduler); Dashboard uses `live_mode=reload` (ApexCharts can't be morphed). Filters survive (re-fetches the current URL); `localStorage.liveUpdates='off'` disables it. See `app/templates/CLAUDE.md` → *Live in-place updates*.
- **Award badges + hash-aware subsets + multi-select** ✅ — collection shows RA award tier (gold **🏅 Mastered** / **✅ Completed** / **🏆 Beaten**; Mastered supersedes) from `LibraryEntry.ra_award` (derived by `services/mastery.py::sync_library_awards` off the local mirror — LOCAL, hardcore-only). Subsets are **hash-aware**: `services/subsets.py::refresh_subset_cache` (the only RA-calling part) enumerates each owned game's subsets + their accepted hashes into `ra_subset_hash`, and `recompute_subset_flags` (LOCAL) marks each ROM `is_subset_rom` + `subset_info` (compatible subsets, each mastered/not). Subset discovery rides the recurring RA passes (autodiscover full sweep + Check-RA/verify scoped) + a manual **Detect subsets** button. Filters: `has_mastered` / `beaten` / `subset_available`. **Multi-select**: per-card/row checkboxes, page-size up to 1000, Select-all-filtered, and a selection bar that runs Hash / Fetch covers / Verify / **Delete** (`/collection/bulk/delete`) on the selection (bulk endpoints read `library_ids` from the request body via `Form`/`hx-vals`). **Sort** (`?sort=`): size (`LibraryEntry.file_size`, migration 0018, set on scan/rehash), date added, progress / achievements / points (RA mirror), title, system. **Delete also clears the matching Wanted record** (`_purge_orphaned_wanted`) — but only once no duplicate/subset copy remains — so deleted games leave the collection. Counts in `/api/status.db.{mastered,beaten,subset_compatible}` + `/api/status.subsets`.

- **Live hunt-download progress + Torrent/Usenet last-resort** ✅ — auto-hunt now creates a per-attempt `Download` card with **real progress + Cancel** (was silent; only created a row on success). And a new **`download_client` extension type** (`extensions/download_client.py`: Prowlarr + qBittorrent + SABnzbd) is the **last resort** when the HTTP sources can't find a verified dump: at hunt exhaustion it submits to qBit/SAB, a scheduler poll (`run_poll_external`) watches the async download, then ingests + **RA-hash-verifies** it into Pending Approval. Single-game / multi-disc (keep all discs) / pack (qBit file-priority trims to the wanted ROM); usenet packs skipped. See `app/services/CLAUDE.md` → *Torrent/Usenet download client*. Needs the rom-finder container to share a mount with qBit/SAB's completed folder.

- **Goals & events tracker** ✅ — `/goals` sets per-game objectives (**master / beat / achievement / custom**) optionally grouped under a free-text **event** label, each with a **deadline**. master/beat/achievement goals **auto-complete** from the local RA mirror via `services/goals.py::evaluate_goals` (LOCAL, **hardcore-only** — softcore awards/unlocks never count; run after a dashboard refresh + on every page load); custom objectives (e.g. "finish level 5") are marked done by hand. The page groups by event with a per-event "N of M done" tally, joins each master/beat goal live to its `RAGameProgress` row for a progress bar/award badge, and shows three-state deadline badges (done / overdue / due-in-Nd). RA games are attached by reusing `/ra/search` (`mode="goal"`). **Achievement goals** are added two ways: the Chrome extension's achievement-page panel (`rom-finder-extension/achievement.js` on `/achievement/*` → `POST /api/goal`), or on the `/goals` page by clicking a search result's **achievement count** to pick one (`GET /ra/games/{id}/achievements`). Either way the goal is **enriched in the background** from `API_GetGameExtended` — its title, **description**, and **badge image** (stored as an absolute `cover_path` and shown on the card) — and auto-completes on a hardcore unlock of that achievement. An **event datalist** (`GET /api/events`, surfaced in the extension + the page) keeps achievement and game goals in the same event group. **Import a whole event** (`POST /goals/import-event`, `services/events.py`): search an event by **name** (`GET /ra/events/search` → RA Events console 101) or paste an RA event/game URL or id → every achievement is imported as a goal in **one** `API_GetGameExtended` call (placeholder tiles skipped; "include already-earned" optional), recorded as a `GoalEvent` that the nightly **`eventsync`** scheduler task re-syncs so growing events (AotW, random rolls) pick up new achievements. Also importable from the **Chrome extension's event-page panel** (`rom-finder-extension/event.js` on `/event/*` → `POST /api/import-event`). **Custom events** (`POST /goals/event`) are named groups with a link (e.g. a Google Sheet) shown in the event header. The page groups by event (header shows the link, ⟳ auto-sync, a progress bar, and the achievement/points tally) and **subdivides multi-game events by game · console**; achievement cards show badge + title + description + game/console + points. A rate-limited **Refresh art** button (`POST /goals/refresh-art`) re-pulls badges + box art (deduped per game). `Goal` columns `achievement_desc`/`points` ship as migrations `0020`/`0021`; `GoalEvent` is a new table (`goal_events`). NB: per-achievement **event point values** and **award-tier names** are RA event-internal data the V1 API doesn't expose, so the header shows a computed done/total + achievement-points progress, not RA's own event score. Live-scope `goals`; state in `/api/status.goals` + the `goals` `/api/changes` scope. See `app/routers/CLAUDE.md` → *Goals* and `app/services/CLAUDE.md` → *Goal auto-completion*.

- **Goals: sub-categories, failed state & custom card art** ✅ — an event can hold **sub-categories** (`GoalCategory` table) each with a **title + date + optional notes** (light safe markdown via `goals._render_notes`, shown below the header, click-to-edit in-pane); a goal's `category` field assigns it. Within an event, **categories and uncategorized games interleave by closest due date** (default page `sort=due`); each category is **collapsible** (click the name or chevron, persisted). A goal can be marked **failed** (`POST /goals/{id}/fail`, manual — never auto): hidden unless the **Show failed** toggle, rendered with a **red ✗ overlay**, and excluded from the event tally. **Custom card art** per goal: **upload an image** (`POST /goals/{id}/image` → `covers/goal_{id}.{ext}`, overrides cover/badge) OR **display text** (e.g. "+100 XP") with a **tinted glyph** (`goals.GOAL_ICONS` + a colour) centered below — priority `custom_image` > `display_text`+`icon` > cover > letter. New `Goal` columns `category`/`custom_image`/`display_text`/`icon`/`icon_color` ship as **migration 0026**; `GoalStatus` gains `failed` (no migration — `status` is VARCHAR); `GoalCategory` is a new create_all table. The **Chrome extension** (manifest **1.9.0**) adds an optional **sub-category** field to both goal panels (`POST /api/goal` `category`) and a **"Hunt immediately after adding"** checkbox on Add-to-Wanted (`POST /api/wanted` `hunt:true` → `auto_hunt`). **A sub-category can be backed by an RA game** (attached **by id or manual search** in the add/edit form's embedded RA game picker, `mode="category"` on `/ra/search`): the category then **takes the game's name** (when no title was typed), its **box art**, **console**, and a **link to its RA page** — title/console/cover land in the background via `goals._enrich_category` (`GoalCategory.ra_game_id`/`system`/`cover_path`, **migration 0027**). The category-assign **dropdown on each goal card is now event-scoped** (`#category-names-{goal.id}` from `_category_names_for_event`) so it lists only that event's sub-categories, not a global mix. The **event-group title** (`<h2>`) is now itself clickable to collapse/expand (was chevron-only — on mobile the small chevron was hard to tap, so tapping the title appeared to do nothing).

- **CHD format check (RetroAchievements codec)** ✅ — opt-in check that flags (and, when `chdman` is available, re-encodes) owned CHDs whose container uses **Zstandard** (`cdzs` for CD, `zstd` for DVD). Such a CHD is a valid, hash-correct dump that plays fine, but RetroArch's *RetroAchievements* hasher (older bundled libchdr) can't decode the zstd hunks, so the game boots yet earns **no achievements**. `services/chd_format.py` reads the CHD v5 header (32 bytes, the four compressor FourCCs — **no binary needed**) and stamps `LibraryEntry.chd_codec` (migration 0024: ""=not-a-CHD/unchecked, "ok"=RA-safe, "cdzs"/"zstd"=needs re-encode). When enabled + `chdman` present it re-encodes via `chdman copy` onto `cdlz,cdzl,cdfl` (CD) / `lzma,zlib,huff,flac` (DVD), **verifying the new Data SHA1 matches the original before swapping** (disc data identical → RA hash unchanged). Gated by the opt-in setting `chd_format_check_enabled`; runs as the manual/daily scheduler **`chdcheck`** task (own `sched_chdcheck_*`, double-gated on the master flag, default off) or its Run-now button. Surfaces as the collection **`bad_chd`** filter + a ⚠ CHD-codec badge, `/api/status.chd`, and a Settings panel (with chdman availability). The Dockerfile installs `chdman` via `mame-tools` — **NB the distro build may be too old to *decode* zstd input**, so in-app convert can fall back to flag-only (reported in `/api/status.chd.chdman_available`); the R: batch scripts with a current chdman remain the reliable re-encode path. This is the in-app twin of those `R:\Roms\<console>\_Convert-to-CHD.bat` scripts.

- **Multiple ROM directories (combined view, cross-dir dedup, console mapping, moving)** ✅ — the library is now the **union of many `LibraryRoot` directories** (new table; `services/library_roots.py`), not a single `download_dir`. **Primary root** = the download target (its `path` is kept == the `download_dir` setting via `library_roots.reconcile_primary_path`, called at the scan/download chokepoints; the Settings ROMs-dir field + "Make primary" both sync it). All **three scan paths** (`collection.bulk_scan`, `library /scan`, `scheduler.run_scan`) walk every root via the shared `library_roots.iter_rom_files` and stamp `LibraryEntry.root_id` (migration 0025); the missing-flag safety guard is now **per-root** (one offline drive can't mass-flag the others). Downloads/hunts/external file into the **primary** root (`library_roots.download_target` → `(base_dir, folder, root_id)`). **Console mapping is per-directory** — each root carries its own `folder_map` JSON in the **folder→system** direction (NOT the legacy global `{system: folder}`), so `psx` in one dir and `Sony PlayStation` in another both group as one console; `dest_folder_for_system` inverts it for filing. **Cross-directory duplicates** are surfaced (not auto-deleted): `_build_collection` flags `cross_dir_dup` when a duplicate group spans >1 root → a fuchsia ⧉ badge, an "Across dirs" filter, a directory `⌂` badge per card/row, a `?root=` directory filter, and the detail panel lists each duplicate copy's directory. **Moving**: single (`POST /collection/library/{id}/move`, inline async, no session held across the copy, `HX-Refresh`) + bulk (`POST /collection/bulk/move`, background `move-batch`) relocate a ROM (+ its `.cue`/`.gdi` tracks) into another root's console subfolder, updating `file_path`+`root_id`; refused on a read-only source/dest or a name conflict. Directories are managed on the **Settings → Library Directories** section (add/remove/set-primary/read-only + per-directory folder→console mapping). State in `/api/status.directories` + the `library` `/api/changes` fingerprint includes `SUM(root_id)` so a move morphs the page live. See `app/services/CLAUDE.md` → *Library roots* and `app/routers/CLAUDE.md` → *Multiple directories*.

## Future Work

- **Set-aware multiset subset support (RA V2 API)** — ROADMAP. RA's modern "multiset" subsets are *achievement sets within one game id*, selected by `?set=N` (e.g. Super Mario 64 = game `10003`, "Coin Collector" = set `9282`). The **V1 API we use (`API_GetGameHashes`) has no set awareness** — it returns a flat game-level hash list (base dump + RAPatches hacks + the subset's patched ROM all lumped, no per-set tag), and the official `api-js` client is V1-only. So today we **cannot** tell which set a hash unlocks, whether a subset is base-ROM-playable vs **patch-required**, nor capture the set id (we only store game id 10003). Proper support requires RA's **V2 API** (`GET /api/v2/games/{id}?include=achievementSets,hashes`, `X-API-Key` header): `achievementSets[]` gives the set id (= `?set=`), `title`, and `type` (`core/bonus/challenge/specialty/exclusive` → bonus/challenge = base-compatible, specialty/exclusive = patch-required); `hashes[]` gives `compatibility` (`compatible`/`patch-required`/…) + `patchUrl`. **V2 docs source (found): `https://github.com/Chew/RA-api-docs/tree/feat/v2-docs/docs/v2`** (OpenAPI). V2 is JSON:API on a SEPARATE host **`https://api.retroachievements.org/v2`** (not the Cloudflare-gated `retroachievements.org` web host). Confirmed-relevant shapes: **`/events/{id}`** → attributes `{title, badgeUrl, state, playersTotal, achievementsPublished, activeFrom, activeThrough}` + relationship **`awards`** (the Bronze/Silver/Gold/Champion tiers — `user-awards` has `kind`/`title`/`badgeUrl`/`displayOrder`); **`/achievements/{id}`** → `points`, `pointsWeighted`, `badgeUrl`, `type`, `unlocksHardcore`/… + relationships **`games`** (the achievement's SOURCE game/console) and `achievementSet`; **`/games/{id}`** + **`/games/{id}/hashes`**. This gives the Goals event header its tiers/points and per-achievement source game. **V2 is now LIVE + wired** (confirmed 2026-06: Bearer auth + `Accept: application/vnd.api+json`, not Cloudflare-gated). Wired so far: **event award tiers** (`/events/{id}?include=awards` → `GoalEvent.tiers_json`, migration 0022, rendered as the Bronze→Champion ladder) and **per-achievement source game · console** (`/achievements/{id}?include=games.system` → updates each event achievement goal's game/console; `services/events.py::enrich_source_games`). Confirmed dead ends: **per-achievement deadlines** (only event-level `activeThrough` exists). Also wired: **V2 box-art cover source** (`cover_sources/ra_v2_boxart.py`, `imageBoxArtUrl`, opt-in) and **set-aware multiset subsets** — `services/game_sets.py::refresh_game_sets` caches each owned game's achievement SETS (`/games/{id}?include=achievementSets,hashes`) into `ra_game_set` (created by create_all), classifying each base-`compatible` (bonus/challenge) vs `patch-required` (specialty/exclusive, with `patchUrl`); shown read-only in the collection detail panel, **alongside** the V1 hash-match subset cache (not replacing it). Refreshed by the "Detect subsets" button. Also wired: **hub import** — `services/hubs.py` + `POST /wanted/import-hub` pulls every game in an RA hub (`/hubs/{id}/games`, paginated) and renders a **filterable, per-game deselectable PREVIEW** (`partials/hub_preview.html`) — RA-style filters (**has achievements** Yes/No/Both from `achievementsPublished`; **your progress** None/Started/Not-beaten/Beaten+/Mastered from the LOCAL `ra_game_progress` mirror via `hubs.progress_bucket`, zero RA calls; **hide owned / already-wanted**, pre-excluded) plus checkboxes; **`POST /wanted/import-hub/add`** then adds only the kept games (each checkbox value is a base64(JSON {id,title,console}) token, so no second RA fetch). V2 exposes **no** game-type (retail/hack) or set-type field, so those RA filters aren't reproducible. Filter/select JS lives in `wanted.html`; covers fetch lazily. Via the Wanted page's "⬇ Import hub" → "Preview hub →" button. Also wired: **median time-to-beat** — `game_sets.refresh_game_sets` captures `medianTimeToBeatMinutes` from the same V2 `get_game` call onto `LibraryEntry.time_to_beat_min` (migration 0023), shown as "⏱ ~Xh" on collection cards + the detail panel. **All four V2 venues now shipped** (event tiers/source-game, box-art cover, set-aware subsets, hub import, time-to-beat). **Blocked/gated on (historical):** auth + Cloudflare reachability — the **`/api/diag/ra-v2?event=<id>&achievement=<id>`** probe (`services/ra_client_v2.py::RAClientV2`) verifies + dumps payload shape. Settings → *Documentation & API references* links the docs source + probe. Interim handling (shipped): the Chrome extension detects a subset page, treats it as the **base game** (sends the sanitized non-`[Subset]` name to Wanted, hunts/owns the base ROM), and warns that patch-required subsets are the user's job to patch. See `rom-finder-extension/content.js` (`isSubsetContext`/`stripSubsetTag`/`updateSubsetUI`).
